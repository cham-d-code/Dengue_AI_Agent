🦟 Sri Lanka National Dengue Prediction System

Complete Model Documentation for Presentation

1. SYSTEM OVERVIEW

What is This?

An AI-powered Early Warning System for dengue outbreaks across all 25 districts of Sri Lanka. The system predicts dengue cases 1-2 weeks in advance, allowing the Ministry of Health to:

  • Pre-position hospital resources (beds, blood units)
  • Deploy vector control teams (fogging, source reduction)
  • Issue public health alerts

Key Capabilities

Feature Description
Coverage All 25 districts of Sri Lanka
Prediction Horizon 1-2 weeks ahead
Update Frequency Weekly
Accuracy MAE ~25 cases, R² ~0.75
Risk Levels Low, Moderate, High, Critical

3. FEATURE ENGINEERING

3.1 Epidemiological Features (Why t-2 Lag?)

The 2-week lag is critical for dengue prediction:

Week 0: Heavy rainfall creates stagnant water (breeding sites)
Week 1: Mosquito eggs hatch, larvae develop (7-10 days)
Week 2: Adult mosquitoes bite humans, virus incubates (4-7 days)
Week 3: Human symptoms appear → CASES REPORTED

Therefore: Weather from 2 weeks ago predicts cases today.

3.2 Complete Feature List

A. Case Lag Features (Epidemic Momentum)

cases_lag_1   # Cases last week
cases_lag_2   # Cases 2 weeks ago
cases_lag_3   # Cases 3 weeks ago
cases_lag_4   # Cases 4 weeks ago
case_velocity = (cases_lag_1 - cases_lag_3) / cases_lag_3  # Acceleration

B. Weather Lag Features (t-2 Lag)

rainfall_lag_1, rainfall_lag_2, rainfall_lag_3, rainfall_lag_4  # mm
temp_lag_1, temp_lag_2, temp_lag_3, temp_lag_4                  # °C
humidity_lag_1, humidity_lag_2, humidity_lag_3, humidity_lag_4  # %
rain_sum_4w = sum(rainfall over last 4 weeks)  # Cumulative breeding

C. Interaction Features (Epidemiological Logic)

rain_hum_interaction = rainfall_lag_2 × (humidity_lag_2 / 100)
# High rain + high humidity = pools don't evaporate = more breeding

cases_rain_interaction = cases_lag_1 × rainfall_lag_2
# "Epidemic Trigger" = Source (existing cases) × Opportunity (breeding sites)

D. Seasonal Features (Monsoon Patterns)

week_sin = sin(2π × week / 52)  # Captures monsoon seasonality
week_cos = cos(2π × week / 52)  # Cyclic encoding

E. Spatial Features (Neighbor Spillover)

neighbor_cases_lag_1 = average cases in adjacent districts last week
# Example: If Colombo has outbreak, Gampaha/Kalutara at higher risk

District Connectivity Map:

Colombo → Gampaha, Kalutara
Kandy → Matale, Kegalle, Nuwara Eliya, Badulla
Jaffna → Kilinochchi
... (all 25 districts mapped)

F. Ecological Zone Features

is_wet_zone   # Colombo, Gampaha, Kalutara, Galle, Matara, Ratnapura, Kegalle
is_dry_zone   # Jaffna, Trincomalee, Batticaloa, Ampara, Hambantota, etc.
is_hill_zone  # Kandy, Matale, Nuwara Eliya, Badulla, Monaragala

Ecological Suitability Index:

# Wet Zone (Rainfall-dominant):
eco_suitability = 0.6×Rain + 0.3×Humidity + 0.1×Temp

# Dry Zone (Humidity-dominant):
eco_suitability = 0.3×Rain + 0.5×Humidity + 0.2×Temp

# Hill Zone (Temperature-limited):
eco_suitability = 0.2×Rain + 0.2×Humidity + 0.6×Temp

G. District Encoding (Baseline Learning)

dist_Colombo, dist_Gampaha, dist_Kandy, ... (25 one-hot columns)
# Model learns: "Colombo normally has 40 cases/week, Nuwara Eliya has 5"

Why Random Forest?

Advantage Explanation

Robust to outliers Historical data has anomalies
No need for scaling Works with raw weather values

Biological Constraints (Post-Processing)

def apply_biological_constraints(predicted_cases, temp):
    """If temperature too extreme, mosquitoes die"""
    if temp > 34 or temp < 16:
        return predicted_cases * 0.4  # 60% reduction
    return predicted_cases

5. RISK CLASSIFICATION

Dynamic Risk Thresholds

Risk is calculated relative to historical baseline for each district:

ratio = predicted_cases / historical_average

if ratio < 1.0:     return "low"
if ratio < 1.5:     return "moderate"  
if ratio < 2.0:     return "high"
else:               return "critical"

Why Relative Thresholds?

District Historical Avg 50 Cases Would Be
Colombo 40 cases/week Moderate (1.25×)
Nuwara Eliya 10 cases/week Critical (5×)

This prevents false alarms in high-volume districts and ensures small districts get attention.

6. RESOURCE ESTIMATION

Hospital Capacity Formulas

HOSPITALISATION_RATE = 0.15        # 15% need admission
AVERAGE_LENGTH_OF_STAY = 4 days
BLOOD_NEED_RATE = 0.05             # 5% need transfusion
BLOOD_UNITS_PER_PATIENT = 4

beds_needed = (predicted_cases × 0.15 × 4) / 7
blood_units = predicted_cases × 0.15 × 0.05 × 4

Example: 100 predicted cases → - 15 hospitalizations - ~9 beds needed (peak occupancy) - ~3 blood units

python scripts/fetch_openmeteo_past_14_days.py

# 2. Generate predictions
python scripts/dengue_forecast_model.py

# 3. Launch dashboard
streamlit run dashboard/app.py
